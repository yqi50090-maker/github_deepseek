# 记忆规范（模板）

> 一句话：**记忆在文件里，不在会话里。** 会话负责干活，文件负责活下去。

## 一、三层归属（同一事实只存一处）

| 层 | 文件 | 读的时机 | 放什么 |
|---|---|---|---|
| **主体** | `~/.dsh/memory/main.md` | 每个对话开场 | 我是谁 / 红线 / 环境 / 约定 / 画像 / 长期结论 |
| **项目分支** | `~/.dsh/skills/projects_memory/<活>/项目信息.md` | 只在该活的会话 | §〇 交接（进度/下一步/卡点）+ §五 决策与坑 |
| **叙事** | `~/.dsh/diary*.md` · `events.jsonl` | 人翻 / 追溯 | 今天发生了什么（append-only） |

**渠道边界**：外部渠道负责读写记忆，不拥有记忆。渠道自己的私房只有运行状态，那不叫记忆。

## 二、记忆怎么增加（三次判断 + 两道门）

```
门 A（宽松）  一周后可能有用吗？      → 是 → 写进当天日记，行尾标 ↑（候选）
门 B（严格）  一周内第二次用到？或本身是规则/红线？
                                     → 是 → 晋升进 main.md §六（带 id），日记那行标 ✓
判断② 归属    换渠道/换活还成立吗？   → 成立→主体；只对本活→项目分支
判断③ 防重    已有同义条目吗？        → 有→改那条，不新增
```

## 三、格式（P1 + id）

```markdown
- 2026-01-01：结论一句话 {#f-001}
- 2026-01-02：铁律级结论 {#f-002 w:2}
```

| 项 | 规定 |
|---|---|
| id | `#f-001` 递增、唯一、不复用；正文大改也不改 id |
| `w:` | 可选人工权重：`w:2` 铁律级 / `w:0.5` 闲话 / 不写=1.0 |
| 一句话 | 一行一条，写成「结论」，不写过程 |

## 四、体量红线

| 对象 | 红线 | 到线怎么办 |
|---|---|---|
| `main.md` | ≤20 KB | 15 KB 起提示分卷，20 KB 硬拒写入 |
| 项目文件 | ≤25 KB | 旧轮次搬 `_archive/` |
| 项目 §〇 | ≤4 KB | 同上 |

> 主体是全量读的，它占的是**每个会话的窗口**，不是一次性开销。

**减肥铁律**：先存快照 → 再搬 → 逐行比对 → 才算没丢。没有快照不许动手。

## 五、反模式

- ❌ 把 token / 密码写进记忆（只写路径）
- ❌ 同一事实在两处各写一份（改时必漏一处）
- ❌ 往记忆里贴长日志、整段代码（存文件、记路径）
- ❌ 拿旧数字判断现在（当场量）
- ❌ 用会话记忆代替文件（会话会被压缩/换掉）
- ❌ 把画像写成揣测（每条画像都要能指到一次具体事件）

## 六、`projects.json`（活清单 · 只存指针）

```json
{ "my_project": { "title": "示例项目", "file": "…/项目信息.md",
    "state": "进行中", "owner": "主会话", "fp": "sha256前16位", "updatedAt": "2026-01-01" } }
```

| 字段 | 含义 |
|---|---|
| `file` | 该活的 `项目信息.md` 路径（唯一真源） |
| `fp` | 文件 sha256 前 16 位，被改动/搬走时比对即报 |
| `state` | 进行中 / 挂起 / 待开工 / 已归档 |
| `owner` | 哪个会话负责（抢写时定位） |
| `conflict` | 两条记录指向同一文件时必须显式标注 |

## 七、`selfNotes.json`（自我认知 · ≤40 条）

| 规矩 | 说明 |
|---|---|
| 谁写 | 我自己（不是别人灌） |
| 何时读 | 只在新会话第一次唤醒读一次 |
| 上限 | 40 条；同一句重复写只刷新 `at` |
| 写什么 | 「我变成了什么样」，不是「发生了什么」 |

## 八、暂不建

- 权重索引 `facts.json`：主体全读阶段用不上
- 执行器脚本：只做只读 check 时再建
- 向量库 / 独立原文库：日记与事件流已在承担
