# Markdown 一键渲染工具 · 使用说明

> 这是一套让 **Markdown 文件双击即看** 的工具，装在 DSH 技能目录里，**全局可用、与具体项目无关**。
>
> 位置：`C:\Users\lenovo\.dsh\skills\md-view\`

## 一、它解决什么问题

Markdown（`.md`）是纯文本格式，**浏览器和 Windows 都不认识它**——双击只会看到满屏的 `#` 和 `|`。

在 VS Code 里看也可以，但要按 `Ctrl+Shift+V`、排版朴素、长文档没有导航，用起来不舒服。

**本工具的做法**：把 `.md` 实时转成带样式的单文件 `.html`，**双击就用浏览器打开渲染好的页面**。

## 二、三个工具，各管一段

| 工具 | 作用 | 谁用它 |
|---|---|---|
| **`md-view.vbs`** | 双击 `.md` 时自动转换 + 打开浏览器 | **系统自动调用**（已设成 `.md` 的默认打开程序） |
| **`md2html.js`** | 真正的转换器：Markdown → HTML | 被上面两个脚本调用，也可命令行直接用 |
| **`批量转换.vbs`** | 把一堆 md 或整个文件夹一次性转完 | **你手动用**（拖拽即可） |

## 三、日常怎么用

### 用法 1：双击单个文件（最常用）

**直接双击任何 `.md` 文件** → 浏览器弹出渲染页面。

第二次双击同一个文件会**明显更快**——工具会检查 `.html` 是否比 `.md` 新，是的话跳过转换。

### 用法 2：批量转换（拖拽）

把**若干 `.md` 文件**或**整个文件夹**一起拖到 `批量转换.vbs` 上：

```
批量转换.vbs  ←  拖入 [文件夹] 或 [多个 .md 文件]
                    ↓
              递归扫描所有 .md
                    ↓
              逐个生成同名 .html
                    ↓
              弹窗报告：成功 N 个 / 失败 M 个
```

非 `.md` 文件（如 `.txt`、`.pdf`）会被**自动忽略**。

### 用法 3：让 AI 生成文档时自动双份输出

这套工具已经注册成一个 DSH 技能 `md-view`。**以后让 AI 写文档、做总结、翻译论文，它会自动同时给出 `.md` 和 `.html`。**

如果某次发现 AI 忘了给 HTML，直接说 **"转 HTML"** 即可。

### 用法 4：命令行

```powershell
& "E:\Node\node.exe" "C:\Users\lenovo\.dsh\skills\md-view\md2html.js" "输入.md" "输出.html"
```

## 四、HTML 长什么样

转出来的 HTML 是**单文件自包含**的（样式内嵌，**断网也能看**），并且比 VS Code 预览多了这些：

| 特性 | 说明 |
|---|---|
| **侧边目录** | 自动从 h1/h2 生成，宽屏常驻，点一下直达章节 |
| **窄屏自适应** | 窗口变小自动收起目录 |
| **表格美化** | 斑马纹 + 悬停高亮，比预览清楚 |
| **中文字体优化** | 微软雅黑优先，行高 1.85 |
| **打印样式** | `Ctrl+P` 可直接存成 PDF |
| **好分享** | 发给同学，对方双击就能看，不用装任何东西 |

**支持的语法**：标题、表格、代码块、引用块、有序/无序列表、分隔线、粗体、斜体、行内代码、链接。

## 五、怎么撤销

### 撤销文件关联（不想让双击跳浏览器了）

双击 `_还原关联.reg` → 确认导入 → 重启资源管理器。

### 只临时换个打开方式

右键任意 `.md` → **打开方式** → 可以选：

- **Markdown（自动渲染）** ← 默认，跳浏览器
- **Visual Studio Code** ← 想改源码时选这个

### 完全卸载

删掉整个文件夹即可，不影响任何其他东西：

```
C:\Users\lenovo\.dsh\skills\md-view\
```

## 六、注册表改了什么（透明说明）

设了这几个**仅当前用户**的键：

```
HKCU\Software\Classes\.md
    (默认值) = "MarkdownAutoView"

HKCU\Software\Classes\MarkdownAutoView\shell\open\command
    = wscript.exe "...\md-view.vbs" "%1"

HKCU\Software\Classes\.md\OpenWithProgids
    MarkdownAutoView
    VSCode.md
```

**注意**：`VSCode.md` 是 **VS Code 自己的 ProgId**，本工具**没有覆盖它**——只把 `.md` 的默认值指向了独立新建的 `MarkdownAutoView`。这样 VS Code 升级时不会把关联改回去。

原始状态已备份在 `_reg_backup_原始关联.reg`。

## 七、已知的技术陷阱（改脚本前必读）

### 陷阱 1：`.vbs` 文件里的中文会导致死锁

wscript 用 **ANSI/GBK** 读取无 BOM 的 `.vbs`。脚本里只要出现中文字面量，就会被解析成乱码并触发**模态语法错误对话框**。

**症状极具误导性**：双击没反应、进程卡住、**连日志都不写一行**。

| 文件 | 编码 | 能否含中文 |
|---|---|---|
| `md-view.vbs` | 纯 ASCII | ❌ **绝对不能** |
| `批量转换.vbs` | UTF-16LE（有 BOM） | ✅ 可以 |

**改 `md-view.vbs` 时，报错信息一律用英文。**

### 陷阱 2：同类问题在 PowerShell 上也存在

PowerShell 5.1 读取**无 BOM 的 UTF-8 脚本**时按 GBK 处理，含中文路径的脚本会解析失败。

**修法**：写文件时加 BOM —— `"\uFEFF" + 内容`。

### 陷阱 3：不要覆盖别的软件的 ProgId

`VSCode.md`、`Code.exe` 这类 ProgId 由对应软件管理。占用它们会在软件升级时被静默改回。

**正确做法**：新建自己的 ProgId，只改 `.md` 的默认值。

## 九、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 .md 无反应 | 脚本里混入了非 ASCII 字符 | 改回纯英文；`Get-Process wscript \| Stop-Process -Force` 清理卡住进程 |
| 弹窗问"你要如何打开" | 系统 UserChoice 在抢 | 去「设置 → 默认应用」把 `.md` 指给 VS Code，或右键勾选"始终" |
| 打开了 VS Code 的源码 | 关联没生效 | 重启资源管理器；或双击 `_还原关联.reg` 后重新设置 |
| 表格没渲染 | 缺 `\|---\|` 分隔行 | 在表头下补一行分隔行 |
| 转换后 HTML 没更新 | 增量跳过逻辑 | 删掉旧 `.html` 再双击，或直接改一下 `.md` 的修改时间 |
| 想开调试日志 | — | 设环境变量 `MDVIEW_DEBUG=1`，日志在 `%TEMP%\md-view.log` |
